## 결정

- 제목은 "Popular Articles"가 부담스러워 **Most Read**. 순위 느낌을 줄이려 번호를 뺐다
- 순위는 글 단위 합계(ko+en). 두 언어가 같은 목록을 쓴다
- 다음 단계(/admin 복사 버튼 → GitHub Actions 자동 커밋)는 `featured.json`을 쓰는 쪽만 바꾼다

## 진행 방식

Superpowers 서브에이전트 방식. 구현 Task 1·2 haiku, Task 3 sonnet, 작업별 리뷰 sonnet(셋 다 첫 리뷰 통과), 최종 리뷰 opus.

## 최종 리뷰가 잡은 것

- **목록 검사는 `pnpm test`에만 있고 빌드에는 없다.** Cloudflare 빌드는 `next build`만 돌린다.
  오타·삭제·draft인 slug은 조용히 빠지고, 전부 틀리면 섹션이 사라진다. 1단계는 사람이 `pnpm test`를 돌리니 괜찮지만
  3단계(Actions)는 이 검사를 건너뛸 수 있다 → 설계에 "목록을 쓰는 쪽은 커밋 전에 `pnpm test`" 명시.
  더 강하게 하려면 프로덕션 빌드에서 목록이 공개 글과 안 맞으면 던지게 바꾼다 (보류)
- slug은 대소문자를 구분한다(`Oxc`). GA4 경로로 목록을 만들 때 소문자로 바꾸면 안 된다 → 설계에 명시
- 남긴 Minor: `JSON.parse` 오류에 파일명이 없음, `role="list"` 없음(사이트 전체 공통), 날짜는 상대 시간 없이 원문
