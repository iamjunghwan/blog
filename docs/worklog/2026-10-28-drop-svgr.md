# @svgr/webpack 걷어내기

**날짜** 2026-10-28
**브랜치** `main`

## 왜 했나

GitHub Security 탭에 Dependabot 경고가 84건(열린 알림 91건) 쌓여 있었다.
"왜 이렇게 많냐"에서 시작했다.

### 먼저 확인한 것 — 방문자에게는 한 줄도 안 간다

경고에 뜬 패키지들의 출처를 따라가 보니 전부 빌드 도구였다.

| 경고 패키지 | 출처 | 쓰임 |
|---|---|---|
| `flatted` | `eslint` | 린트 캐시 |
| `minimatch` | `@eslint/eslintrc` | 린트 설정 |
| `source-map-js` | `@svgr/webpack` | SVG 변환 |
| `svgo` | `@svgr/webpack` | SVG 최적화 |
| `nanoid` | `@tailwindcss/typography` | CSS 생성 |

GitHub 화면에도 전부 `Transitive` 라고 붙어 있고 `pnpm-lock.yaml` 에서 검출됐다고
적혀 있다. 코드가 아니라 잠금 파일을 본 것이다.

배포 산출물 `out/`(97개 파일, JS 608KB)을 통째로 훑어 확인했다.

```
flatted  minimatch  source-map-js  svgo  nanoid  brace-expansion
js-yaml  browserslist  @babel/  tailwindcss  postcss  undici  cheerio
→ 전부 흔적 없음
```

유일하게 걸린 `eslint` 40건은 Oxc 글 본문에 적힌 **글자**였다.

`output: "export"` 라 빌드가 끝나면 HTML·CSS·JS만 남고 도구는 사라진다.
그래서 이 경고들은 실제 노출이 아니다.

### 그래도 줄일 수 있는 것은 줄였다

경고를 없애려고 억지로 버전을 올리는 건 의미가 없다 — 전이 의존성이라
부모 도구가 올려주기 전에는 손댈 수 없고, `overrides` 로 강제하면 도구가 깨진다.

대신 **도구 자체가 필요한지**를 봤다. `@svgr/webpack` 이 babel·svgo를 포함해
117개를 끌고 오는데, 정작 SVG를 컴포넌트로 import 하는 곳은 **4군데**였다.

## 한 일

### 아이콘 4개를 직접 적었다

`components/Icon/` 에 네 개를 만들었다.

| 이전 | 이후 | 비고 |
|---|---|---|
| `public/MenuToggle.svg` | `MenuToggleIcon.tsx` | `currentColor` |
| `public/search.svg` | `SearchIcon.tsx` | `currentColor` |
| `public/darkMode.svg` | `DarkModeIcon.tsx` | 색 고정 |
| `public/lightMode.svg` | `LightModeIcon.tsx` | 색 고정 |

`<img>` 로 바꾸지 않은 이유는 앞의 둘이 `stroke="currentColor"` 를 쓰기 때문이다.
글자색을 따라가야 하는데 `<img>` 로는 안 된다.

각 컴포넌트는 `React.SVGProps<SVGSVGElement>` 를 그대로 받아 넘기므로
`className="w-6 h-6"` 같은 기존 사용법이 안 바뀐다.

### 지운 것

- `@svgr/webpack` 의존성
- `next.config.ts` 의 webpack·turbopack SVG 로더 설정 (설정 파일이 4줄로 줄었다)
- `public/` 의 SVG 6개 — 쓰던 4개 + Next 템플릿 잔재 `file.svg`·`next.svg`

산출물 JS는 1KB 늘었다. 아이콘 마크업이 인라인으로 들어가는데, svgr도 결국
같은 일을 하고 있었으므로 차이가 거의 없다.

## 남은 83건은 어떻게 할까

전부 `eslint` 와 `tailwindcss`·`postcss` 체인이다. 둘 다 빌드에만 쓰이고
산출물에 안 들어간다. 선택지는 셋이다.

1. **그대로 둔다** — 노출이 없으므로 가장 합리적이다
2. 개별 알림을 Dismiss → `Risk is tolerable` 로 닫는다
3. `pnpm lint` 가 이미 깨져 있으므로(Next 16이 `next lint` 를 없앴다)
   eslint 체인을 손볼 때 같이 정리한다

3번은 별건이다 — `eslint-config-next` 를 16으로 올리려면 `eslint.config.mjs` 를
flat config로 다시 써야 한다. 시도해 봤고 `FlatCompat` 로는 순환 참조로 터진다.
