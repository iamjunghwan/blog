# CLAUDE.md 추가

**날짜** 2026-11-18
**브랜치** `main`
**파일** `CLAUDE.md` (신규)

## 무엇을 했나

프로젝트 루트에 `CLAUDE.md`를 만들었다. Claude Code가 세션마다 읽는 파일이라,
아티클을 쓸 때 매번 설명하지 않아도 되도록 이 블로그의 핵심 규칙을 모아 뒀다.
첫 줄의 `@AGENTS.md`로 기존 Next.js 지침을 함께 불러온다.

처음에는 11개 절로 자세히 썼다가, 핵심만 남기도록 줄였다 (약 60줄).
세부 문법은 `docs/writing-posts.md`, 스크립트는 `scripts/README.md`로 링크만 건다.

## 담은 내용

| 절 | 내용 |
|---|---|
| 아키텍처 | md → `app/lib/posts/` → 라우트 → `out/` → Cloudflare Pages. 완전 정적, 파이프라인 모듈, 라우트, i18n, 스크립트, 테스트 |
| 글 위치 | `content/posts/ko\|en/`, 같은 slug이 한 쌍, `pnpm new-post`, slug 변경 주의 |
| 글 쓰기 | 본문 구조, `-다`체, 표·`text` 블록, 확인한 것만, 영어판 `description`, 기존 태그 |
| 마무리 | 이미지 경로, `pnpm thumbnail <slug>`, `pnpm fonts`, test·build |
| 작업 방식 | 커밋은 승인 후, gitmoji 메시지, 작업 기록 |

문체·구조 규칙은 기존 글을 조사해 정했다. 예를 들어 마무리 소제목은 다수인 `## 정리` / `## 참고`로 맞췄다
(`## 참고` 11편, `### 참고` 2편). 영어판 `description`은 en 24편 모두에 있고 ko에는 없다.

## 발견한 것

- **README와 `docs/writing-posts.md`의 글 경로가 낡았다.** `content/posts/<year>/<month>/`로 적혀 있지만
  실제로는 `content/posts/ko|en/<year>/<month>/`다. 이번엔 고치지 않았다.
- `.github/workflows/blog_cd.yml`은 예전 AWS ECS 배포 설정으로 전부 주석 처리돼 있다.

## 검증

문서만 추가해 코드·빌드에 영향이 없다. 테스트는 돌리지 않았다.

## 사용자가 할 일

- 글을 써 보면서 Claude가 반복하는 실수가 있으면 CLAUDE.md에 한 줄씩 더한다
- README·writing-posts.md 경로 수정, 안 쓰는 workflow 파일 정리 여부 결정
