# 메인 화면 재구성 — 최신 글 5개를 가로 카드로, 날짜에 상대 표기 추가

- 작성일: 2026-10-14
- 상태: 설계 승인됨

## 배경

메인(`/`)은 최신 글 5개를 3단 그리드 + 아랫줄 2개로 보여 준다. 두 가지 문제가 있다.

**1. 아랫줄 카드가 윗줄보다 1.6배 크다.**

`MainArticleList`의 아랫줄은 `<li>` 하나가 `md:col-span-3`으로 3칸을 전부 차지하고,
그 안에서 카드 2개가 `flex-1`로 절반씩 나눠 갖는다.

| | 칸 너비 |
|---|---|
| 윗줄 카드 3개 | `(720 − 64) ÷ 3` ≈ 219px |
| 아랫줄 카드 2개 | `(720 − 8) ÷ 2` ≈ 356px |

예전에는 썸네일이 96×96 고정이라 티가 나지 않았다. 2026-10-14에 카드 썸네일을
`w-full`로 바꾸면서 칸 너비 차이가 그대로 드러났다. 간격도 윗줄만 `gap-8`(32px),
아랫줄 안쪽은 `gap-2`(8px)로 어긋나 있다.

**2. 768px 안에서 3단은 너무 좁다.**

본문 컨테이너가 `max-w-3xl`(768px, 좌우 패딩 제외 720px)이다. 3단으로 나누면
카드 한 장이 219px이라 제목이 3~4줄로 접히고 발췌문이 들어갈 자리가 없다.
"최신 글을 읽게 만든다"는 메인의 목적에 가장 불리한 배치다.

별개로, 날짜가 `2026-10-14` 절대 표기뿐이라 **얼마나 최근 글인지 바로 와닿지 않는다.**

## 목표

메인을 **최신 글을 바로 읽게 만드는 입구**로 만든다.

- 최신 글 **5개**를 한 줄에 하나씩 보여 준다 (개수는 지금과 같고, 배치가 바뀐다)
- 제목이 접히지 않고 **발췌문까지** 보이게 한다
- 맨 아래 "모든 글 보기"로 전체 목록에 연결한다
- 최근에 올라온 글인지 날짜만 보고 알 수 있게 한다

### 범위에서 제외 (YAGNI)

- 본문 컨테이너 폭(`max-w-3xl`) 변경 — 글 읽기에는 적절한 폭이다. 메인만을 위해 바꾸지 않는다
- 태그 바로가기, 소개 영역 등 메인에 새 섹션 추가 — 헤더에 이미 Posts/About이 있다
- 검색 모달의 날짜 표기 — 한 줄이 좁아 상대 표기를 넣으면 답답해진다
- 페이지네이션·Posts 목록의 레이아웃 변경 — 이번 작업과 무관하다

## 확정된 결정

### 결정 1: 메인 배치는 "가로 카드 세로 스택"

썸네일을 왼쪽에, 글 정보를 오른쪽에 두고 한 줄에 하나씩 세로로 쌓는다.

```
┌──────────────────────────────────────────────┐
│              The Latest Article              │
│ ──────────────────────────────────────────── │
│ ┌──────────┐  2026-10-14 (오늘)              │
│ │ 썸네일    │  ai · react                    │
│ │ 40:21    │  AI를 활용하면서 개발자의 책임    │
│ └──────────┘  AI에게 기능을 맡기면 빠르다…    │
│ ──────────────────────────────────────────── │
│ ┌──────────┐  2026-10-12 (2일 전)            │
│ │ 썸네일    │  swe-bench · ai                │
│ └──────────┘  SWE-bench 점수가 말해주지…      │
│ ──────────────────────────────────────────── │
│ ┌──────────┐  2026-09-16                     │
│ │ 썸네일    │  npm · javascript              │
│ └──────────┘  npm은 왜 tgz로 패키지를 올릴까  │
│ ──────────────────────────────────────────── │
│           … 같은 모양으로 5개까지 …            │
│ ──────────────────────────────────────────── │
│                 모든 글 보기 →                │
└──────────────────────────────────────────────┘
```

가로폭 720px을 한 줄이 전부 쓰므로 제목이 한 줄에 들어가고 발췌문 2줄이 확보된다.

한 줄의 높이는 썸네일(224×118px) 기준 약 150px이다. 5줄이면 본문이 약 750px로,
헤더를 포함해도 한 번 정도 스크롤하면 끝까지 보이는 분량이다.

**검토한 대안**

- *맨 위 1개를 히어로로 크게.* 최신 글은 확실히 눈에 띄지만 720px 폭에서 40:21
  이미지는 높이가 378px이라 첫 화면을 거의 다 차지한다. 전용 썸네일이 없는 글이
  대부분이라 기본 로고가 그만큼 크게 깔린다.
- *3단 그리드를 균일하게 정리.* 변경은 가장 작지만 219px이라는 근본 제약이 남는다.

### 결정 2: 3+2 분기를 구조째 제거한다

`md:col-span-3` / `flex-1` 분기와 `posts.length > 3` 게이트, `slice(3, 5)`를 모두 없앤다.
세로 스택은 글 개수에 따라 분기할 필요가 없으므로 **크기가 어긋날 여지 자체가 사라진다.**

보여 줄 개수(5개)는 호출자인 `app/page.tsx`의 `slice(0, 5)` 하나로만 정해진다.
지금은 호출자의 `slice(0, 5)`와 컴포넌트의 `slice(0, 3)`/`slice(3, 5)`가 겹쳐 있어
한쪽만 고치면 글이 사라지거나 레이아웃이 깨졌다. 그 이중 관리가 없어진다.

### 결정 3: 메인 카드와 Posts 목록 행을 합치지 않는다

둘 다 "가로 카드"지만 썸네일 위치가 반대고(메인은 왼쪽, 목록은 오른쪽) 발췌문 유무가
다르다. 하나로 합치면 `thumbnailSide`, `showExcerpt` 같은 플래그만 늘어난다.
공통 조각은 이미 `components/Card/*` atom으로 공유되고 있으므로 그 패턴을 따른다.

### 결정 4: 상대 날짜는 브라우저에서 계산한다

이 블로그는 `output: "export"` 정적 사이트다. **빌드 시점에 "N일 전"을 계산하면
배포 순간의 값이 HTML에 박힌다.** 글이 한 달에 한 편꼴이라 "2일 전"이라고 적힌 채로
한 달 내내 서 있게 된다.

그래서 `CardDateArea`를 클라이언트 컴포넌트로 바꾸고, 마운트 후에 상대 표기를 덧붙인다.

| 시점 | 출력 |
|---|---|
| 빌드 / SSR | `2026-10-14` |
| 마운트 후 | `2026-10-14 (오늘)` |

서버와 클라이언트의 첫 렌더가 같으므로 hydration 경고가 나지 않고, 값은 항상 정확하다.

### 결정 5: 상대 표기는 30일 이내 글에만 붙인다

가장 오래된 글이 2025-01이라 약 640일 전이다. `640일 전`은 한눈에 감이 오지 않는다.
30일을 넘으면 아무것도 붙이지 않고 날짜만 보여 준다. 상대 표기를 **"새 글이다"라는
신호**로만 쓴다.

| 경과 | 표기 |
|---|---|
| 0일 | `2026-10-14 (오늘)` |
| 1일 | `2026-10-13 (어제)` |
| 2~30일 | `2026-09-16 (28일 전)` |
| 31일 이상 | `2026-07-09` |

적용 범위는 **메인 + Posts 목록**. 두 곳이 같은 `CardDateArea`를 쓴다. 검색 모달은
날짜만 그대로 둔다.

## 컴포넌트 구조

```
app/page.tsx                          최신 5개를 넘긴다 (slice(0, 5) 그대로)
└── MainArticleList                   세로 스택 + "모든 글 보기"
    └── MainArticleItem  (신규)        가로 카드 한 줄
        ├── CardImageArea             썸네일 (기존)
        ├── CardDateArea              날짜 (클라이언트화)
        ├── CardTagsArea              태그 (기존)
        ├── CardTitleArea             제목 (기존)
        └── CardExcerptArea  (신규)    발췌문 2줄
```

`MainArticleItem`의 반응형:

- 모바일: `flex-col` — 썸네일이 위, 글이 아래
- `sm` 이상: `flex-row` — 썸네일 `w-56`, 글이 나머지

썸네일 비율은 `aspect-[40/21]`로 기존 카드와 같다. og:image 표준(1200×630)과 같은
값이라 `pnpm thumbnail`로 만든 이미지가 어디서도 잘리지 않는다.

## 날짜 계산

**`app/lib/date/relative.ts`** — 순수 함수

```
relativeLabel(date: string, now: Date): string | null
```

- `date`는 `"YYYY-MM-DD"`. `parsePost`가 이 형태로 정규화해 두므로 다른 형식은 들어오지 않는다
- 30일 초과면 `null`. 호출부는 `null`이면 아무것도 붙이지 않는다
- **`now`를 인자로 받는다.** 그래야 테스트에서 시간을 고정할 수 있다

**시간대 처리.** `new Date("2026-10-14")`는 UTC 자정으로 해석된다. 한국(UTC+9)에서
그대로 비교하면 하루가 어긋난다. 연·월·일을 쪼개 **보는 사람의 로컬 자정**으로
`Date`를 만들고, 오늘도 로컬 자정으로 맞춰 일수를 센다.

미래 날짜(예약 발행 등)는 `null`을 반환해 아무것도 붙이지 않는다.

## 위험과 대응

- **`CardDateArea`가 클라이언트 컴포넌트가 된다.** Posts 목록도 같이 쓰므로 그쪽에도
  작은 JS가 붙는다. 날짜 하나짜리 컴포넌트라 번들 증가는 미미하고, 목록 자체는
  서버 렌더를 유지한다.
- **상대 표기가 마운트 후에 나타난다.** 절대 날짜는 처음부터 보이고 괄호만 뒤에
  붙으므로 레이아웃이 밀리지 않도록 괄호 영역을 인라인으로 둔다.
- **`ArticleCard` 삭제.** 메인 외에서 쓰이지 않는지 구현 전에 다시 확인한다.
