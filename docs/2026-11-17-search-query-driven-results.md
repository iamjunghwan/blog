# 검색 모달 — 검색어가 있을 때만 결과를 그린다

2026-11-17

## 왜

모달을 열기만 해도 글 전체가 깔렸다. 글이 24편까지 늘면서 그 목록이 화면을 넘겼다.

원인은 `filterByTitle` 이었다. 검색어가 비면 전체를 돌려주고, 모달은 그걸 그대로
그렸다. 검색은 찾는 행위다. 아직 아무것도 찾지 않은 상태의 답은 전체가 아니라
없음이다.

## 무엇을 했나

### 1. 빈 검색어의 답을 바꿨다

`app/lib/posts/queries.ts` 의 `filterByTitle` 이 빈 검색어·공백뿐인 검색어에
빈 배열을 준다. 소비처가 검색 모달 하나뿐이라 (`grep` 으로 확인) 규칙을 한곳에서
바꿀 수 있었다.

테스트를 먼저 고쳐 실패를 보고(1 fail) 구현을 바꿨다.

```
- test("filterByTitle은 빈 검색어와 공백만 있는 검색어에 전체를 준다")
+ test("filterByTitle은 빈 검색어와 공백만 있는 검색어에 아무것도 주지 않는다")
```

### 2. 빈 결과를 두 가지로 나눴다

빈 배열이 두 가지 뜻이 됐다 — 아직 안 찾았거나, 찾았는데 없거나. 둘을 같은
"검색 결과가 없습니다." 로 그리면 모달을 연 사람에게 거짓말이 된다.

`useSearchData` 가 `hasQuery` 를 같이 준다. 모달이 그걸로 문구를 고른다.

| 상태 | 문구 |
|---|---|
| 검색어 없음 | `searchHint` — "글 제목으로 찾습니다. 검색어를 입력해 보세요." |
| 검색어 있고 결과 없음 | `noResults` — "검색 결과가 없습니다." |

`searchHint` 를 `messages.ts` 에 ko · en 양쪽으로 넣고 `pnpm fonts` 로 서브셋을
다시 만들었다 (한글 786자, 220KB).

### 3. 결과 영역에 천장을 뒀다

검색어를 넣어도 일치가 많으면 모달이 다시 길어진다. 근본 원인은 결과 수에 따라
모달이 자란다는 점이었다.

```
max-h-[min(400px,50vh)] overflow-y-auto
```

고정 높이(`h-`)로 먼저 해 봤는데 검색어가 없을 때 400px 빈 상자가 남아서
천장만 두는 쪽으로 바꿨다. 뷰포트가 낮은 기기에서는 400px도 과해서 절반까지만
쓴다.

목록 `key` 를 배열 인덱스에서 `item.slug` 로 바꿨다. 타이핑할 때마다 목록이
바뀌는 자리라 인덱스 키는 재사용이 어긋난다.

### 4. 모달을 위에 붙였다

천장을 둬도 타이핑하는 동안 창이 계속 움직였다. 모달이 세로 가운데 정렬
(`items-center`)이라 결과 수에 따라 모달이 자랄 때 위쪽 모서리가 같이 올라갔다.
입력창이 글자를 칠 때마다 위아래로 흔들렸다.

```
- flex items-center justify-center
+ flex items-start justify-center px-4 pt-[10vh]
```

위를 기준으로 두면 제목과 입력창의 y 가 고정되고 목록만 아래로 자란다.
같은 줄에 겹쳐 있던 죽은 클래스(`w-full max-w-xl` + `w-full max-w-md`)도
이 참에 정리했다. `max-w-xl` 이 이기고 있었다.

## 검증

브라우저에서 직접 쟀다 (`.local/shots/` 의 `searchcheck.mjs`, `searchmany.mjs`,
`searchfixed.mjs`).

| 상태 | 줄 | 패널 | 모달 / 뷰포트 |
|---|---|---|---|
| 검색어 없음 | 0 | 100px | 250 / 900 |
| `"AI"` (2건) | 2 | 72px | 222 / 900 |
| `"a"` (15건) | 15 | 400px, 스크롤 | 550 / 900 |
| 일치 없음 | 0 | 100px | 250 / 900 |

입력창이 실제로 고정되는지는 검색어를 `"" → AI → a → zzz없음 → 를 → e → ""`
로 바꿔 가며 y 좌표를 쟀다. 세 뷰포트 모두 값이 하나였다.

| 뷰포트 | 입력창 y | 모달 아래 (최대) |
|---|---|---|
| 1440×900 | 158px (고정) | 640 / 900 |
| 390×844 | 152px (고정) | 634 / 844 |
| 800×500 | 118px (고정) | 450 / 500 |

- 모바일 390×844, 낮은 뷰포트 800×500 에서도 모달이 화면을 넘지 않는다
  (500px 높이에서는 천장이 50vh = 250px 로 내려간다)
- 영문 화면에서 `Searches post titles. Start typing.` 확인
- `"AI"` 가 거르는 두 편이 실제로 제목에 AI 가 든 글과 일치한다

| 항목 | 결과 |
|---|---|
| `tsc --noEmit` | 통과 |
| `npx eslint` (바꾼 파일) | 깨끗 |
| `pnpm test` | 147/147 |
| `pnpm build` | exit 0, html 94개 |

## 손대지 않은 것

모달 상자가 `bg-white` 뿐이고 `dark:` 변형이 없다. 다크 모드에서 배경이 흰색으로
나온다. 안쪽 글자는 `dark:text-gray-500` 을 쓰고 있어 대비가 어긋난다. 이번 요청
밖이라 두었다.
