# 영어판 만들기

대상 slug: $ARGUMENTS

## 절차

1. 한국어 원문을 찾는다: `content/posts/ko/**/<slug>.md`
2. 영어판 뼈대를 만든다 — **원문 날짜를 물려받으므로 반드시 스크립트로:**
   ```bash
   pnpm new-post <slug> "<English title>" <원문과 같은 태그> en
   ```
   이미 영어판이 있으면 그 파일을 고친다 (원문 수정 반영).
3. frontmatter를 원문과 맞춘다:

   | 필드 | 규칙 |
   |---|---|
   | `slug` `date` `tags` | 원문과 **동일** |
   | `thumbnail` | 원문에 있으면 **같은 경로** |
   | `title` | 영어 제목. 본문 `# 제목`과 같은 문장 |
   | `description` | **필수.** 영어 1~2문장, 155자 안팎. 글의 핵심 주장과 숫자를 담는다 |
   | `draft` | 원문과 같게 |

4. 본문을 옮긴다 (아래 원칙).
5. 확인: `pnpm dev` → `http://localhost:3000/en/<slug>`, 그리고 `pnpm test`.
6. 커밋은 사용자 승인 후 `📝 post: <주제> 영어판`.

## 옮기는 원칙

- **구조는 1:1.** 소제목 개수·번호, 표, 코드블록, 이미지 위치를 원문과 맞춘다.
- **문장은 직역하지 않는다.** 영어 기술 블로그 독자에게 자연스러운 문장으로 쓴다. 짧고 단정한 톤은 유지한다.
- 코드와 명령 출력은 그대로 둔다. 코드 **주석**과 `text` 다이어그램 속 한국어 설명만 옮긴다.
- 한국어 독자만을 위한 맥락(국내 서비스, 말장난)은 풀어 쓰거나 덜어낸다.
- 링크는 그대로. 원문이 한국어 자료를 가리키면 영어 자료가 있는지 찾아본다.

## 소제목 대응

| 한국어 | 영어 |
|---|---|
| `## 정리` | `## Summary` |
| `## 참고` | `## References` |
| `## 1. 숫자가 먼저다` | `## 1. The Numbers First` (번호 유지, Title Case) |
