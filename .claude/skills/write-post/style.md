# 문체 가이드

기존 글(특히 Scion, TypeScript 증분 검사)에서 뽑은 규칙이다.

## 문장

- **평서문 `-다`체.** `-습니다`, `-요`는 쓰지 않는다.
- 문장은 짧게 끊는다. 한 문단은 2~4문장.
- 과장·단정을 피한다. 적용 범위의 한계는 한 문단으로 짚는다.

## 도입

정의로 시작하지 않는다. **구체적인 상황·경험·숫자**로 연다.

> 빌드할 때마다 **약 48초**가 걸렸다.

> 넉 달 만에 12배 이상 증가했다.

도입 끝에서 이 글이 무엇을 파는지 한 문장으로 밝힌다.

## 강조

- 문단의 핵심 한 문장을 **굵게**. 한 문단에 하나 이하.
- 기술 용어는 처음 나올 때 원어를 괄호로: `파생 데이터(derived data)`.

## 보여 주기

| 무엇을 | 어떻게 |
|---|---|
| 비교, 전후 수치 | 표 |
| 명령 출력, 흐름, 다이어그램 | ` ```text ` 블록 |
| 실제 코드 | 언어를 적은 코드블록 |
| 인용할 숫자 한 줄 | `>` 인용 |

## 남의 글을 다룰 때

- "원문에 따르면…", "글이 밝힌 수치다"처럼 출처를 문장에 드러낸다.
- 자체 보고 수치는 "독립 벤치마크는 아니다"라고 밝힌다.
- 내 해석은 "이게 설계의 핵심이라고 본다"처럼 주어를 분명히 한다.

## 마무리

- `## 정리`에서 본문을 반복하지 말고 **독자에게 남는 질문이나 판단 기준**으로 끝낸다.
- `## 참고`는 원문을 맨 위에, 링크마다 한 줄 설명을 붙인다.
